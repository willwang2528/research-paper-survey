## 面向读者的逐篇介绍：固定开头

最终报告、synthesis.md 或独立论文介绍中，每篇论文先按以下顺序展示，再展开机制、结果、适配性与局限。首行标题只写完整英文题名，不在题名前添加编号、简称或评价；标题级别随文档层级调整。下例是 Markdown 模板，不是待输出的 YAML。

```markdown
### <完整英文题目>

- <完整中文标题翻译>
- <YYYY-MM-DD> ｜ <会议/期刊及 track（适用 CCF 等级或必要限定）> <YYYY-MM>
- 作者单位：<单位 A；单位 B；……，去重；中国机构中文，其他机构英文>
- <已核验的最新版 arXiv URL，包含 vN>
- 摘要总结：<一小段中文，说明研究问题、核心方法和作者报告的主要结果；保留重要条件。>
```

展示规则：日期行不加“arXiv 最新版：”“收录：”“收录年月：”等字段名，也不重复版本号；版本号由链接中的 vN 表达。会议/track 后直接接年月，以空格连接，不另加分隔符或日期口径说明。中文题名作为标题后的第一个无序列表项，不加“中文题目：”；第二项为日期与收录信息；第三项单独展示“作者单位：”，中国院校、公司及研究机构用中文，其他机构用英文，不双语并列；第四项直接放链接，不加前缀（支持点击时使用同 URL 的链接标签）。摘要总结继续保留在链接下一项，用户只简化开头时不得顺带删除摘要。

排版示例（仅示范格式，不代替执行时核验）：

```markdown
### OpsMem: Dual-Memory Reasoning with Cross-Memory Resonance for Failure Diagnosis

- OpsMem：通过跨记忆共振实现故障诊断的双记忆推理框架
- 2026-07-13 ｜ ISSRE 2026 Industry Track（主会 CCF B；本篇等级适用性待核实） 2026-10
- 作者单位：南开大学；清华大学；华为技术有限公司
- https://arxiv.org/html/2607.11357v1
- 摘要总结：<经核验后填写的问题、方法与主要结果。>
```

核验与填写规则：

- **最新版**：在本次查询截点核对 arXiv 版本历史，用最近版本的提交/更新日期及显式版本 URL（如 `/abs/<id>vN` 或已确认可访问的 `/html/<id>vN`），不要用首次提交日期替代。最新版本与实际阅读版本不同，紧接开头注明所读版本及日期，不把旧版机制或数字归给新版。论文没有可核实 arXiv 时，日期位置写“arXiv 日期未核实”，链接项直接给正式论文 URL，在证据记录中说明；访问失败或版本未知标“待核实”，不猜版本号。
- **收录**：优先以官方论文集、会议目录、出版方页面核验完整 venue、年份和 track，区分已录用、已发表、预印本、投稿中。CCF 等级以当前可查的官方目录及适用口径为准，并在证据笔记记录目录版次与链接；workshop、companion、industry 等不能仅因挂靠同名主会就继承主会等级，适用性未确认则注明。未找到正式收录证据时，面向读者仅写“预印本”，不追加“未核实正式收录”“未核实到正式会议收录”等说明；核验状态、已查来源和日期保留在证据记录中，不能推断已被拒稿。
- **收录年月**：优先采用正式出版年月；只核实录用年月或会期时可展示该年月，但其确切口径、来源和未确认项放在收录证据记录中，必要时让会议文字链接到对应官方来源，不在首行重复解释。不能据此把会期当作已知录用日期，也不能用 arXiv 更新时间替代。只核实年份时保留年份，不补造月份；未核实收录时保留预印本状态并省略收录年月，不堆叠“不适用”。
- **中文标题**：忠实翻译完整题名，保留专有方法名，不把自己的评价加入标题；独占标题后的第一个无序列表项，位于日期行之前。
- **全部作者单位**：核对所展示 arXiv 版本的论文署名页及作者—单位映射，收集所有作者的全部署名单位（含学校、企业、研究机构及双重署名），按机构去重；同一机构的院系合并，不把不同法人机构或联合实验室成员随意合并。展示时中国院校、公司及研究机构使用已核实中文名称，其他机构使用论文署名中的英文名称；各单位只展示一种语言，不附双语对照。机构归属按署名主体核实，不根据作者姓名或邮箱猜测。原始署名、机构归属及名称映射保存在证据记录。已有英文署名时不能因缺少中文译名写成“中文名待核实”；确实无法确认名称或归属时保留原署名，在证据记录中说明，不杜撰译名或漏掉该单位。不只列第一/通讯作者单位，也不使用作者当前主页单位替代论文署名。只能核实部分时明确“已核实单位：…；其余待核实”，不能声称完整。
- **摘要总结**：一般 2–4 句，不逐句翻译；交代问题、方法、主要结果。仅依据摘要的收益写“作者报告”，不添加摘要没有的规模或因果结论；全文限定和自身判断在后续分析中区分。避免将微服务 trace 自动解释为 Agent trace。
- 在工作笔记保存以上字段的来源 URL、原文位置与核验日期；元数据行中的收录信息可直接附来源链接。开头不能被跨论文比较表替代；概览表可以另行保留。

脚本生成的 `report.md` 是审计草稿，目前不自动采集所有作者单位、CCF 或版本历史，也不自动总结摘要。agent 须据本模板补齐面向读者的逐篇介绍；脚本 strict 通过不代表这些元数据已核验。仅调整展示格式时，不改变纳入条件、评审决定或范围指纹。

不能用笔记存在代替本人理解，不能把仓库存在写成已复现。

## synthesis.md

```text
1. 范围：问题、硬条件、日期口径、检索截点与报告状态。
2. 领域地图：按子问题与路线组织，各路线的假设、输入输出、证据和局限。
3. 关键比较：每个比较连接到论文的具体版本与证据。
4. 阅读顺序：地图/综述 → 奠基 → 近期路线 → 关键对照 → 未决问题；逐项说明理由。
5. 逐篇清单入口：核心、背景、排除与待核验，引用 report.md 和 reviews.jsonl。
6. 未决问题：区分论文作者结论、跨论文推断、自己的可检验假设。
7. 覆盖与限制：来源、返回上限、缺失全文、失败接口、种子检查和停止原因。
8. 学习状态：哪些只是发现/生成笔记，哪些已能解释/运行/复现。
```

## 最终人工验收

- 范围、日期、类型和硬条件清楚，协议变更有记录；所有决定已按当前范围复核，scope_fingerprint 正确。
- 全部核心身份、实际阅读版本、正式发表状态有原始依据。
- 每篇介绍以英文题名开头，依次给出中文题名、日期与收录行、独立作者单位行、无前缀最新版 URL、摘要总结；保留“作者单位：”标签，中国机构中文、其他机构英文且去重，会议后空格接年月。日期口径留在证据记录，CCF 适用性与未知项不隐瞒。
- 全部核心逐项满足硬条件，无用偏好抵消 no/unclear 的情况。
- 所有主要机制、数字和比较能回原文，结论条件未遗漏。
- 元数据、全文证据、综合推断、迁移设想有区分。
- 日志保留实际查询/时间/范围/失败，原始记录与工作数可区分。
- 所有覆盖 done 都有实查证据，not_applicable 有理由；protocol_fingerprint 对应当前协议，每条计划查询有最新成功记录。
- 背景、预印本、待核验和排除状态清楚，不夸大检索完整性。
- 笔记、理解、运行、复现状态分别陈述。
- 版本、commit 和反馈可追溯；公开交付没有 key 或私有凭据。
