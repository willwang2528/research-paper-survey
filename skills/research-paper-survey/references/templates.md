## venue-scan.md（选择会议目录补查时）

```text
会议 / 年份或届次 / track：
官方目录 URL / 访问日期：
选择该会议及届次的理由：
计划浏览范围（session、页段或完整目录）：
实际浏览范围 / 已浏览条目数 / 计划范围总数（未知则注明）：
标题无预设关键词但摘要可能相关的候选（题名、URL、理由）：

```

目录浏览用于发现候选，不是全文阅读或符合需求的证明；不要求逐篇精读无关论文。覆盖状态按预先约定的范围和实际记录判断。

## synthesis.md

```text
1. 范围：问题、硬条件、日期口径、检索截点与报告状态。
2. 领域地图：按子问题与路线组织，各路线的假设、输入输出、证据和局限。
3. 关键比较：每个比较连接到论文的具体版本与证据。
4. 阅读顺序：地图/综述 → 奠基 → 近期路线 → 关键对照 → 未决问题；逐项说明理由。
5. 逐篇清单入口：核心、背景、排除与待核验，引用 report.md 和 reviews.jsonl。
6. 未决问题：区分论文作者结论、跨论文推断、自己的可检验假设。
7. 覆盖与限制：来源、返回上限、缺失全文、失败接口、种子检查和停止原因。
8. 学习状态：哪些只是发现/生成笔记，哪些已能解释/运行/复现。
```

## 最终人工验收

- 范围、日期、类型和硬条件清楚，协议变更有记录；所有决定已按当前范围复核，scope_fingerprint 正确。
- 全部核心身份、实际阅读版本、正式发表状态有原始依据。
- 全部核心逐项满足硬条件，无用偏好抵消 no/unclear 的情况。
- 所有主要机制、数字和比较能回原文，结论条件未遗漏。
- 元数据、全文证据、综合推断、迁移设想有区分。
- 日志保留实际查询/时间/范围/失败，原始记录与工作数可区分。
- 所有覆盖 done 都有实查证据，not_applicable 有理由；protocol_fingerprint 对应当前协议，每条计划查询有最新成功记录。
- 背景、预印本、待核验和排除状态清楚，不夸大检索完整性。
- 笔记、理解、运行、复现状态分别陈述。
- 版本、commit 和反馈可追溯；公开交付没有 key 或私有凭据。
