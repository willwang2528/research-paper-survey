# 研究与学习工作流

方法版本：0.1.0。此流程面向领域学习和近期工作梳理；正式系统综述还需领域适配的预注册协议、质量/偏倚评价、独立复核和综合方法。

## 阶段 1：需求协议

明确用途、研究对象、问题、场景、时间、论文类型、必要证据、阅读预算。区分硬条件和偏好；不能以加权评分让高引用补偿对象不符。

时间至少区分首次公开、正式发表、所读版本更新日。旧文今年修订不自动成为今年的新工作；索引入库日期也不是发表日期。协议选 `first_public` 或 `formal_publication`，全文验收补对应证据。基础工作可超窗作为背景。

将需求编号 R1…Rn。协议改变时记录原因、日期和版本，重新检查受影响条目；不要先看到结果再悄悄改标准。

退出条件：每个核心候选将如何被判断已清楚；查询范围和停止条件可执行。

## 阶段 2：术语、来源与查询设计

建立对象、问题、场景、方法、评测五组术语，记录全称、缩写、同义表达、歧义和种子出处。先组合对象与问题，之后补场景，避免一开始过多 AND 限制。NOT 前先检查是否会误删。

| 来源 | 职责 | 限制 |
|---|---|---|
| Semantic Scholar | 关键词发现、引用网络 | 网页、relevance API、bulk API 能力不同；模式应记录 |
| OpenAlex | 结构化检索和元数据 | 日期/身份仍需原始来源核对；认证与限额会变化 |
| arXiv | 新预印本、首发与修订 | moderation 不是同行评审；updated 不是 first published |
| Google Scholar | 广覆盖、不同版本、相关文献 | 人工/浏览器辅助；不承诺脚本自动抓取、全量导出 |
| 官方论文集/期刊 | 接收身份、track/type、目录补漏 | 会议名称不等于主会 Full/Regular 身份 |
| DBLP/OpenReview | 元数据导航、审稿与决定线索 | OpenReview 投稿页面不代表已接收 |
| 作者主页/仓库/博客/综述 | 术语、线索、实现 | 科学主张回原论文；开源链接不等于复现 |

每个平台单独构造查询。不要把 Semantic Scholar 网页不支持布尔语法的规则推广到所有 API；也不要把 bulk 查询直接套到 relevance。arXiv 排序发生在匹配结果内，不会撤销关键词。

用已知种子校准：未命中可能源于未收录、语法、术语、字段或日期。种子应来自多个群体与路线；报告种子覆盖不等于全领域召回率。

退出条件：`protocol.json` 有真实查询与来源分工；每个限制知道如何记录。

## 阶段 3：多路检索和归并

执行查询后保留原始响应、实际式子、provider/mode、日期字段、排序、时间、返回和导出范围、是否截断、失败。零结果与接口失败分别处理。

四路互补：关键词 → 不同群体种子 → 前向/后向引用 → 最新官方目录与作者补查。引用扩展可能带回窗口外文献，须按协议验收；用于奠基阅读的放背景。

DOI/arXiv 精确匹配优先，保留 provenance 和来源观察值。标题相似只提示可能重复。核对会议版/预印本及期刊扩展的差异，保留实际读到的版本 URL；当前 `papers.jsonl` 主要记录工作级候选，不声称已有完整版本图谱。需要时增加人工 `versions.md`。

退出条件：本轮计划已执行或记录阻塞；来源、截断和归并有据可查。

## 阶段 4：初筛和全文验收

标题摘要用于宽松初筛，明显不符才排除。关键未知进入全文检查；没有全文不能既当 core，也不能仅因此断言不相关。

按三层验收：

1. 身份：题名、作者、ID、版本、发表状态及官方页面。
2. 适配：每个硬条件的原文位置、证据、理由和 yes/no/unclear。
3. 主张：报告每项核心机制、结果和比较是否被所读版本支持。

| 证据问题 | 核对对象 |
|---|---|
| 真正解决哪个问题 | 任务定义、输入输出、评测目标 |
| 对比是否公平 | 数据划分、模型能力、工具权限、预算和基线 |
| 效果是否可信 | 样本/任务数、指标分母、重复试验、标注来源 |
| 改善归于何处 | 消融、控制实验；理论工作的假设与推导 |
| 能否迁移 | 模型、任务长度、环境、数据分布和资源差异 |
| 能否复用 | 代码/数据存在、已获取、已运行、已复现分别标注 |

CCF A/B 是 venue 层面信号，需核对当时目录和具体 track/type。不要把 Workshop、Findings、Demo、Short 直接写成主会长文等级。引用量有年龄偏差，不能据此排掉最新论文。

四类决定：core、background、excluded、pending。全部核心论文逐篇验收，不能只抽样。对于关键论文，可让另一核验者从原文重读；相同模型一致不是独立事实证明，也不是正式人工双筛。

退出条件：所有决定有理由，core 全硬条件通过；证据不足的明示 pending。

## 阶段 5：覆盖与停止

逐篇适配性和整体覆盖是两个问题。覆盖检查包括已知种子、替代术语、不同引用圈、近期会议目录、新预印本、反例/否定结果、边界排除复审。

完成约定来源、查询批次和引用轮次；检查核心不确定项；记录新增工作是否趋少及预算。预算用尽时可交付阶段草稿，不能写成穷尽检索。未检查前 N 条以外的结果、未取得全文、接口失败和缺失来源必须显式列出。

`coverage.json` 的 done 必须有实际证据；not_applicable 必须有任务相关理由。不能把“脚本没有这个接口”当作已覆盖该渠道。

退出条件：覆盖检查和停止理由有据可查，未决项在报告中可见。

## 阶段 6：综合、报告和学习

运行 audit/report，再由 agent 写 `synthesis.md`。脚本只依据结构化记录渲染，不代替跨论文判断。按问题、路线、假设、证据和局限组织，而不是每篇摘要拼接。

阅读顺序通常是地图/综述 → 奠基 → 近期路线 → 关键对照 → 未决问题。采用三遍法分配精力。每篇至少回答真实问题、旧方法失败条件、输入输出、关键设计、替代方案、证据边界以及与邻文差异。

计数区分检索记录、来源重复、独立工作、实际文献版本、全文审查和四类决定。脚本未追踪的过程计数不要补造，人工补充时标明方法。

退出条件：领域地图、证据卡、日志、限制和阅读路线齐全；所有主要主张可回查。

## 阶段 7：更新与反馈

更新沿用协议并建立新 run，复跑查询时使用有理由的重叠窗口，覆盖延迟收录；区分新工作、旧文新版本和接收状态变化。记录与旧 run 的关系，不覆盖旧证据。

每次写 feedback，明确观察、证据与改进提案。只有经复现和回归的改动才能进入新版本；流程见 evolution.md。
